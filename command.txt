Here is a breakdown of what each of those three Git commands does for your `backend/Dockerfile`:

### git diff backend/Dockerfile 

**What it does:** Shows you the exact line-by-line changes made to `backend/Dockerfile` compared to the last saved commit. Added lines appear in green (`+`) and removed lines in red (`-`).
**Use case:** Check your work before committing to make sure you didn't accidentally leave in unintended edits.


###  git restore backend/Dockerfile
**What it does:** Discards all uncommitted local changes in `backend/Dockerfile` and restores it back to its state in the most recent commit.
**Use case:** Undo your local edits if you made a mistake or decided you don't want to keep those changes. *(Caution: This cannot be undone).*


### git add backend/Dockerfile && git commit -m "Update Dockerfile
**What it does:** Runs two commands in sequence:
1. `git add backend/Dockerfile`: Stages the modified file, marking it ready to be saved into Git history.
2. `git commit -m "Update Dockerfile"`: Permanently saves those staged changes into the branch's history with the message "Update Dockerfile".
**Use case:** Save your modifications as a permanent checkpoint in your current branch (`develop-b`).
